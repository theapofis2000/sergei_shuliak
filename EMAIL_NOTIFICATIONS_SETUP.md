# Уведомления сайта на электронную почту

Сайт остаётся статическим на GitHub Pages. Supabase вызывает Google Apps Script после сохранения нового сообщения или первого уникального браузера за день. Apps Script уведомляет владельца сайта на `theapofis@icloud.com`, а отправителю контактной формы присылает подтверждение получения. Свой домен не требуется. Отправителем будет Google-аккаунт, владеющий Apps Script. Секреты хранятся в Script Properties и Supabase Vault; браузер их не получает.

## 1. Создайте Apps Script

1. Откройте [script.google.com](https://script.google.com/) под Google-аккаунтом, с которого будут отправляться уведомления, и создайте проект.
2. Откройте файл `Code.gs` в этом репозитории, скопируйте его содержимое в редактор Apps Script вместо стартового кода и сохраните.
3. Сгенерируйте случайный секрет в Terminal:

   ```sh
   openssl rand -hex 32
   ```

   Сохраните его в менеджере паролей. Не вставляйте секрет в файлы сайта, GitHub или чат.

4. В Apps Script откройте **Project Settings** (значок шестерёнки) → **Script Properties** → **Add script property** и добавьте:

   | Property | Value |
   | --- | --- |
   | `EMAIL_NOTIFICATION_TO` | `theapofis@icloud.com` |
   | `EMAIL_NOTIFICATION_WEBHOOK_SECRET` | Сгенерированная строка из шага 3 |

5. Нажмите **Deploy → New deployment**. Выберите тип **Web app**, настройте **Execute as: Me** и **Who has access: Anyone**, затем нажмите **Deploy**. При первом запуске Google попросит разрешить отправку почты от вашего аккаунта.
6. Скопируйте URL развернутого приложения. Он должен заканчиваться на `/exec`. Сохраните его как пароль: URL не добавляется в публичный код сайта.

## 2. Сохраните адрес и секрет в Supabase Vault

В Supabase откройте **Database → Extensions**, найдите `pg_net` и включите его, если он ещё не включён.

Затем откройте **SQL Editor**. Для каждого значения выполните `vault.create_secret`, подставив URL и тот же случайный секрет. Выполняйте запросы отдельно и не сохраняйте их как публичные SQL-сниппеты:

```sql
select vault.create_secret('ВСТАВЬТЕ_URL_ПРИЛОЖЕНИЯ_С_КОНЦОМ_exec', 'email_notification_webhook_url');
```

```sql
select vault.create_secret('ВСТАВЬТЕ_СЛУЧАЙНЫЙ_СЕКРЕТ', 'email_notification_webhook_secret');
```

## 3. Обновите Apps Script

Скопируйте обновлённый `google-apps-script/Code.gs` в редактор Apps Script и сохраните. После каждого изменения кода, включая автоответ отправителю, откройте **Deploy → Manage deployments → Edit**, выберите **New version** и нажмите **Deploy**. URL приложения и Script Properties обычно остаются прежними.

## 4. Включите подсчёт уникальных браузеров

Если проект Supabase уже работает со старым счётчиком, откройте `supabase/unique_visitors.sql`, скопируйте запрос в **Supabase → SQL Editor** и выполните его. Он создаёт закрытую таблицу дневных ID и дневную сводку, а также включает новую RPC-функцию. Старые дневные просмотры в `daily_visits` сохраняются.

## 5. Установите триггеры базы

Откройте обновлённый `supabase/email_notifications.sql`, скопируйте запрос в **Supabase → SQL Editor** и выполните. Он вызывает Apps Script при новом сообщении в `contact_messages` и только при первом уникальном браузере за день. Повторные загрузки не отправляют новые письма.

## 6. Проверьте отправку

1. Отправьте тестовое сообщение через форму сайта: запись должна появиться в Supabase, уведомление — прийти на `theapofis@icloud.com`, а подтверждение — на адрес, указанный в форме. В подтверждении можно ответить напрямую: `Reply-To` ведёт владельцу сайта. Чтобы форму нельзя было использовать для многократной рассылки на один адрес, автоответ этому адресу отправляется не чаще одного раза за 15 минут; уведомление владельцу продолжает приходить для каждого сохранённого сообщения.
2. Откройте сайт в новом приватном окне или другом браузере: значение в `daily_unique_visits` увеличится, и при первом посещении после установки триггера придёт одно уведомление за UTC-день. Обычная перезагрузка в том же браузере число не меняет. Если сводка за сегодня уже создана до включения триггера, письмо о посещении начнёт приходить со следующего UTC-дня.
3. Если письма нет, проверьте **Apps Script → Executions** и **Supabase → Database → Logs**. Вызовы `pg_net` выполняются асинхронно. Google перенаправляет ответ Content Service на отдельный URL, поэтому в `net._http_response` может отображаться `302`; факт отправки проверяйте в **Apps Script → Executions** и во входящих письмах.

Счётчик оценивает уникальные браузеры в пределах суток, но не может точно определить уникальных людей: другой браузер или очистка localStorage создаст новый ID. IP-адреса и контактные данные в таблице посещений не сохраняются. Уведомление о посещении отправляется только один раз за UTC-день, при первом ID. Google указывает лимит 100 получателей писем в сутки для личных аккаунтов; каждое сообщение формы теперь расходует две отправки — владельцу и автору, поэтому квота может закончиться быстрее. При превышении дневного лимита отправка может остановиться до его сброса. [Текущие квоты Apps Script](https://developers.google.com/apps-script/guides/services/quotas).

Если меняете код Apps Script, создайте новую версию развертывания через **Deploy → Manage deployments → Edit → New version**. URL обычно остаётся прежним; если он изменится, обновите секрет `email_notification_webhook_url` в Supabase Vault.
